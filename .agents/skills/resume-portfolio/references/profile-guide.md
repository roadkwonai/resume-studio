# profile.json 작성 안내

규격의 원본은 `shared/profile.ts` 이다. 여기에는 이력서를 옮길 때의 판단 기준만 적는다.

## 이력서 항목 대응

| 이력서 | profile.json |
| --- | --- |
| 이름, 희망 직무 | `basics.name`, `basics.label` |
| 자기소개서, 경력 요약 | `basics.summary`(2~3문장), `basics.about`(문단 배열) |
| 경력 | `work[]`. 담당 업무는 `summary`, 성과는 `highlights` |
| 프로젝트 | `projects[]`. 문제/해결/결과가 있으면 `problem`, `solution`, `result` |
| 성과 수치 | 프로젝트별은 `projects[].metrics`, 대표 수치는 `metrics` |
| 학력 | `education[]` |
| 수상, 자격증 | `awards[]` |
| 보유 기술 | `skills[]`. 그룹으로 묶는다 |
| 블로그, 발표 | `writing[]`(본문이 있을 때만), 없으면 링크를 `basics.profiles` 에 |
| GitHub | `basics.profiles`, 대표 저장소는 `openSource.repos` |
| 추천사 | `testimonials[]`. 실제 작성자가 있는 글만 |

## 쓰는 법

- `basics.headline`: 사이트 첫 화면 문장이다. 이 사람이 무엇을 하는지 한 줄로, 한글 25자 안팎. 이력서의 표현에서 뽑는다. 이력서에 재료가 없으면 직무와 전문 분야를 그대로 쓴다.
- `basics.summary`: 여러 템플릿이 첫 화면이나 소개 첫 줄에 크게 쓴다. 그래서 경력 나열로 쓰면 사이트 얼굴이 회사 이름 목록이 된다. "어떤 문제를 푸는 어떤 사람인지"를 쓰고 회사 이름은 넣지 않는다. 회사 이야기는 `work` 에서 나온다. 예: "(주)가상물류에서 API를 개발합니다"보다 "물류 서비스의 백엔드를 만드는 개발자입니다. 배차와 주문 처리 시스템을 맡아 왔습니다."
- `basics.about`: `summary` 를 되풀이하지 않는다. 같은 문장이 한 페이지에 두 번 나오면 내용이 없어 보인다.
- `locale`: 사이트 언어. 이력서 언어와 다르게 요청받으면 번역하되 고유명사는 공식 표기를 쓴다.
- 날짜는 `YYYY` 또는 `YYYY-MM`. 재직 중이면 `end` 를 비운다.
- `slug` 는 영문 소문자, 숫자, 하이픈만. 한글 이름의 프로젝트는 뜻을 살린 영문으로 정한다.
- `skills[].items[].progress`, `level`: 이력서에 숙련도가 적혀 있을 때만 넣는다. 숫자를 짐작해 넣지 않는다. `years` 도 이력서에서 계산되는 경우만 넣는다.
- `projects[].metrics`: 경력 항목에 적힌 수치를 프로젝트에 옮길 때는 같은 일이라는 근거가 있어야 한다. 짐작으로 옮겼다면 보고에서 사용자에게 확인을 받는다.
- `metrics`: 이력서에 있거나 그 내용에서 바로 계산되는 값만 쓴다. "경력 9년"처럼 재직 기간에서 나오는 수치는 괜찮다.
- `services`, `process`, `faq`, `now`, `uses`, `contact.budgets`: 프리랜서나 사이드 프로젝트 맥락이 있을 때만 쓴다. 구직용이면 대개 비운다. 사용자가 말하지 않은 가격이나 서비스를 만들어내지 않는다.
- `features.legal`: 기본은 넣지 않는다. 개인 사이트에 약관 페이지는 대개 필요 없다.
- `basics.availability`: 사용자가 말한 경우에만 쓴다.

## 모자란 자료 다루기

꼭 필요한 값은 이름, 직무, 첫 문장, 요약, 소개, 메일이다. 메일이 이력서에 없으면 사용자에게 묻는다. 나머지는 비워 두고 마지막 보고에 "이것을 주면 이 섹션이 살아납니다"로 알린다. 작업 중에 여러 번 묻지 말고 모아서 한 번에 묻는다.

## 예시

이력서: "2021.03~현재 ○○페이 백엔드 개발, 정산 배치 처리시간 6시간→40분"

```json
{
  "company": "○○페이",
  "position": "백엔드 개발자",
  "start": "2021-03",
  "summary": "정산 배치와 결제 백엔드를 개발합니다.",
  "highlights": ["정산 배치 처리 시간을 6시간에서 40분으로 단축"]
}
```

직함이 이력서에 "백엔드 개발"로만 있다면 `position` 을 "시니어"처럼 올려 적지 않는다.
