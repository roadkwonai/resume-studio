# 자료가 여럿이거나 많을 때

이력서 외에 노션, 경력기술서, 예전 메모가 함께 오면 읽는다. 자료 하나만 있으면 이 문서는 필요 없다.

## 읽기

노션 공개 페이지는 자바스크립트로 그려져서 `curl` 로는 빈 페이지가 온다. 브라우저로 열고, 긴 페이지는 스크롤하면서 글을 모은다. 화면 밖 블록은 그려지지 않기 때문이다. 하위 페이지는 전부 읽지 말고 싣기로 한 프로젝트만 연다. 사용자 폴더에 내보낸 사본이 있어도 날짜가 지났을 수 있으니 페이지 목록은 원본과 대조한다.

## 자료끼리 다를 때

이메일, 경력 연수, 기여도, 수치가 자료마다 다른 일은 흔하다. 어느 쪽이 맞는지는 본인만 안다.

- 연락처처럼 하나를 골라야 하는 값은 수정일이 가장 최근인 자료를 쓴다.
- 기여도나 성과 수치처럼 틀리면 곤란한 값이 충돌하면 화면에서 빼거나 어느 쪽에서도 틀리지 않는 표현을 쓴다. 예를 들어 기여도가 70%와 100%로 갈리면 기여도 없이 "개발했습니다"로 쓴다.
- 다른 값은 빠짐없이 모아 마지막 보고에 "자료 A는 이렇고 자료 B는 이렇다. 이쪽을 썼다"로 알린다. 고른 값을 말없이 넘기면 사용자는 충돌이 있었는지조차 모른다.

## 추리기

웹 이력서의 독자는 1분 안에 판단한다. 상세 내용은 이력서 파일과 링크로 보낸다.

- 프로젝트는 대표작 4~6개. 최근 것, 수치가 있는 것, 서비스 주소가 살아 있는 것을 먼저 고른다. 경력의 무게가 한쪽으로 쏠리지 않게 주력 분야의 프로젝트를 꼭 넣는다.
- 뺀 프로젝트는 `work[].summary` 에 이름만 남긴다. 한 회사의 성과가 사라지지 않게 하기 위해서다.
- 오래된 경력은 한 문장으로 줄이되 회사와 기간은 지우지 않는다. 경력 공백처럼 보이면 안 된다.
- 프로젝트 상세 페이지가 있으면 링크로 연결한다. stackbit-os 는 `extras["stackbit-os"].caseStudies` 를 쓴다.
- 고른 프로젝트와 뺀 프로젝트를 보고에 적는다.
