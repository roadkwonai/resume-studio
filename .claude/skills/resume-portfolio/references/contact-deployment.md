# 문의 메일과 배포

## 선택과 설정

수신 이메일과 발신 방식(Gmail SMTP, Resend 등), 배포 대상이 확정되지 않아 기능이 달라진다면 사용자에게 묻는다. Gmail 주소를 Resend의 인증된 발신 도메인으로 오인하지 않는다. `.env.example`을 `.env.local`로 복사할 때 기존 파일은 덮어쓰지 않는다. 비밀값은 사용자에게 채팅으로 보내라고 요구하지 않고 로컬 환경 파일 또는 서비스의 비밀 설정에 직접 넣게 안내한다. 실제 키, 인증 파일 및 개인정보는 로그, Git, 브라우저 번들, `NEXT_PUBLIC_` 변수에 넣지 않는다.

- Gmail: [Google 앱 비밀번호 안내](https://support.google.com/accounts/answer/185833)를 안내한다. 2단계 인증이 필요하고 계정 유형·보안 설정에 따라 사용이 제한될 수 있다. 해당 Gmail 계정과 발급한 앱 비밀번호를 서버에서만 사용한다. 앱 비밀번호는 일반 계정 비밀번호가 아니다. 별도의 발신 도메인은 필요 없다.
- Resend: [API 키](https://resend.com/docs/dashboard/api-keys/introduction)와 [도메인 인증](https://resend.com/docs/dashboard/domains/introduction)을 안내한다. 테스트용 발신 주소는 수신자 제한이 있으므로 실제 외부 발송에는 인증된 발신 도메인을 준비한다. Gmail 주소만 입력한다고 발신 도메인이 인증되는 것은 아니다.
- Vercel: 로그인된 CLI를 우선 사용하고 필요할 때 [토큰 발급](https://vercel.com/docs/rest-api/reference/authentication)을 안내한다. 토큰은 배포 CLI용이며 앱 런타임에 올리지 않는다. [환경 변수](https://vercel.com/docs/cli/env)는 실제 코드가 읽는 이름으로 필요한 환경에만 등록하고 새 배포에 반영한다. 인증정보를 명령 인자나 셸 히스토리에 노출하지 않는다.

예시 환경 변수는 기능을 자동 설치하거나 연결하지 않는다. 구현 시 선택한 제공자에 필요한 패키지와 서버 경로를 추가하고 `.env.example`의 변수명을 실제 코드와 일치시킨다. 수신 주소와 발신 계정이 다르면 각각 명확히 설정한다.

## 구현과 검증

서버측 입력 검증, 요청 크기 제한, 스팸·남용 방지 방안, 시간 제한, 실패 처리와 실제 성공/실패 UI를 마련한다. 메일 헤더에 임의 개행을 허용하지 않고 사용자 주소는 `replyTo`에 사용한다. 실패 로그에 인증정보나 문의 본문을 남기지 않는다. 구현과 호스팅의 API 런타임 호환성을 확인한다.

설정되지 않은 경우 오류를 명확히 보여 준다. 유효하지 않은 요청과 설정 누락, 성공/실패 응답을 검사한다. 사용자가 테스트 발송을 허용한 경우 테스트 메일을 수신함에서 확인한다. API 성공만으로 수신을 확인했다고 말하지 않는다. 외부 발송과 배포는 기존 사용자 요청 범위에서만 실행하고 무제한 재시도하지 않는다.
