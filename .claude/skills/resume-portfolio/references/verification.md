# 웹 이력서 검수

## 요구 목록과 표시 결과

작업 전 입력 자료와 사용자 요청을 기준으로 점검표를 만든다. 프로젝트별 이름·분류·우선순위·서비스/저장소 URL·이미지, 기술별 연차·아이콘, 성과의 출처, 헤더 버튼·PDF·문의 방식을 기록한다. 없는 값과 사용자 요청에 따라 삭제한 링크도 구별한다. 작업 후 데이터, 실제 렌더링 화면/DOM, 파일 응답을 각각 대조해 누락·미검증 항목을 표시한다. 빌드 성공이나 HTML 전체 문자열 검색은 카드별 표시를 증명하지 않는다.

## 내용과 표현

- 이력서, Notion, 사용자 답변에 대조해 이름, 경력, 연차, 직무, 성과, 프로젝트별 역할과 기술을 확인한다. 불확실한 수치는 묻거나 빼고, 프로토타입을 실제 운영 성과로 표현하지 않는다.
- 요청한 모든 프로젝트와 분류, 우선순위, 프로젝트별 서비스 및 GitHub 링크, 삭제 요청이 반영됐는지 목록으로 대조한다. 프로젝트 이미지가 있다면 해당 프로젝트와 일치하는지 확인한다.
- 프로젝트 이미지와 아이콘이 정상 로드되는지 실제 렌더링을 확인하고, 만료 URL이나 접근 제한 이미지는 교체한다. 사용할 수 없는 경우 숨기거나 대체 표시하고 보고한다.
- PDF 버튼이 지정한 파일을 내려받는지 원본과 해시를 비교하고, 포트폴리오 링크·새 창 설정·연락처 등 각 버튼을 확인한다. 데모 인물이나 가짜 수치가 남아 있지 않은지 확인한다.

## 화면과 기능

- 선택한 원본 템플릿과 실제 결과를 데스크톱과 모바일에서 처음부터 끝까지 비교한다. 섹션, 테두리와 카드, 스택 아이콘·연차·막대, 성과 지표, 프로젝트 이미지, 코드 영역의 내용과 스크롤, 메뉴·애니메이션 등 원본의 주요 요소 및 요청한 변경을 확인한다. 데이터 부족이나 사용자 의도로 생략한 것은 구분한다.
- 스크롤, 줄바꿈, 가로 넘침, 깨진 이미지, 빈 공간, 작은 화면에서의 터치 및 키보드 조작을 살핀다. 원본과 동일한 가짜 경력·성과는 복사하지 않는다.
- `npm run verify -- <절대경로>`와 독립 프로젝트의 `npm run check`를 실행한다. 해당 프로젝트에 check가 없으면 가능한 lint/typecheck/build를 각각 실행한다. 브라우저에서 상호작용과 네트워크 오류를 확인한다.
- 메일 앱을 여는 `mailto:`와 서버가 직접 발송하는 문의 폼을 구분해 요구한 방식이 구현됐는지 확인한다. 문의 폼을 구현했다면 정상·오류 흐름을 확인하고, 테스트 발송이 허용된 경우 실제 수신을 확인한다. 배포했다면 배포 주소에서 이미지, 파일, 링크, 폼을 다시 확인한다. 확인할 수 없는 항목은 사유와 함께 보고한다.
